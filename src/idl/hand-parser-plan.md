## Current parser shape

The current IDL parser consists of these main parts:

- `src/idl/src/scanner.c` and `src/idl/src/scanner.h` implement the scanner.
  This scanner is already hand-written and should remain the token source.
- `src/idl/src/parser.y` is the authoritative grammar and semantic-action
  source for the Bison parser.
- `src/idl/src/parser.c` and `src/idl/src/parser.h` are generated by Bison and
  checked into the source tree.
- `src/idl/src/processor.c` owns `idl_pstate_t`, runs preprocessing/scanning,
  converts `idl_token_t` values into Bison semantic values, and calls
  `idl_yypush_parse`.
- `src/idl/CMakeLists.txt` hashes `parser.y` into the generated files and
  regenerates with Bison if the hash is stale and Bison is available.
- The AST and semantic helpers live in `tree.c`, `annotation.c`,
  `expression.c`, `scope.c`, `symbol.c`, and related headers.

The supply-chain concern is specifically the checked-in Bison output. The
replacement should make the parser source directly reviewable and remove the
need to trust generated C for this part of the tree.

## Target architecture

The replacement parser should be a recursive-descent parser using the existing
scanner and existing AST helpers.

Planned source layout:

- `src/idl/src/parser_impl.h`
  Internal declarations shared by the hand parser and `processor.c` while both
  parsers coexist.
- `src/idl/src/parser_impl.c`
  Token stream, parser entry point, error handling helpers, and grammar
  routines for declarations and types.
- `src/idl/src/parser_expr.c`
  Constant-expression parser. This may also live in `parser_impl.c` at first
  if keeping it together is simpler. Split only when it reduces complexity.
- `src/idl/src/parser_tokens.c`
  Optional compatibility helpers for token names and keyword detection. Add
  this only if keeping generated `parser.h` during the migration becomes
  awkward.

The initial integration should preserve the public `idl_parse` and
`idl_parse_string` APIs. Internally, `processor.c` should be able to dispatch
to either parser while the migration is active. The long-term end state is:

- no Bison dependency for normal builds,
- no checked-in Bison output,
- no `parser.y` needed for correctness,
- all parser behavior expressed in reviewed C source.

## Parser interface design

The hand-written parser should operate on `idl_pstate_t` and return
`idl_retcode_t`, matching the rest of the IDL frontend.

The scanner currently emits `idl_token_t` values with:

- `code`, which is either a character token or an `IDL_TOKEN_*` token code,
- `value`, which owns strings for identifiers, string literals, and
  preprocessor numbers,
- `location`, which carries first and last positions.

The hand parser should introduce a small token stream object with these
responsibilities:

- hold the current lookahead token,
- optionally hold one saved token for simple lookahead,
- free token-owned values that are consumed without being transferred into
  AST nodes,
- expose helpers such as `peek`, `advance`, `accept`, and `expect`,
- centralize syntax-error reporting and EOF handling,
- keep scanner-state transitions compatible with annotation parsing.

Ownership rule for tokens:

- If a token string is transferred to an AST node, the parser must not free it.
- If a token string is discarded, skipped after an error, or used only for a
  comparison, the parser must free it with `idl_free`.
- This rule must be covered by sanitizer runs before switching parser defaults.

## Grammar strategy

Use straightforward recursive descent for declaration syntax and a precedence
parser for constant expressions.

Declaration parsing:

- `parse_specification` parses zero or more definitions until EOF.
- `parse_definition` parses leading annotations and dispatches by the next
  keyword.
- `parse_module` handles `module identifier { definitions } ;` and scope
  push/pop.
- `parse_type_declaration` handles constructed types and typedefs.
- `parse_struct` handles forward declarations, inheritance, and members.
- `parse_union` handles forward declarations, switch type, cases, labels, and
  element specs.
- `parse_enum` and `parse_bitmask` handle enumerator/value lists.
- `parse_const` handles constant declarations.
- `parse_annotation_declaration` and `parse_annotation_application` preserve
  the current annotation state machine.

Expression parsing:

- Preserve the Bison precedence from `parser.y`:
  unary, multiplicative, additive, shift, bitwise and, xor, or.
- Prefer a Pratt parser or one function per precedence level. The latter maps
  directly to the current grammar and is probably easier to audit.
- Reuse `idl_create_*` expression helpers from `expression.c` and the same
  semantic validation performed by the current parser actions.
- Keep literal location information on created expression nodes.

Error handling:

- Report syntax errors through `idl_error`.
- Prefer the current Bison wording where it is helpful and already tested.
- On allocation failure, return `IDL_RETCODE_NO_MEMORY` without leaking
  partially built AST objects.
- On semantic failure, return the helper's `idl_retcode_t` and release local
  parser-owned objects.
- Implement local cleanup labels in grammar routines rather than one large
  parser-wide unwinder.
